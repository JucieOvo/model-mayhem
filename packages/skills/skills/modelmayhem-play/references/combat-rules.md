# Model Mayhem 对战规则

本文件是对战 Agent 的权威规则摘要，也是面向人类的规则说明。规则细节与版本参数由内容包和确定性规则引擎提供；两者冲突时，以服务端工具返回的状态、合法行动和结算结果为准。

## 一、参与者与财团

标准对局只有两个座位：

- 玩家财团。
- 对立财团 Agent。

财团只允许：

- 中国财团。
- 西方财团。

财团身份在档案创建后确定，不通过第一张公司卡临时改变。玩家与 Agent 始终使用相反财团。

阵营限制只作用于组织中的公司据点：

- 本财团公司可以进入牌组并部署。
- 对方财团公司不能进入牌组，也不能部署。
- 全球平台、云服务、硬件与基础设施不触发公司锁。
- 技术、论文、开放权重、开源和开放科学资产可以跨财团使用。
- 对方闭源模型默认不能跨财团使用，除非当前规则或效果明确授予访问权。

每套蓝图牌组必须声明财团，并至少包含一张本财团公司卡。

## 二、对局目标

首先将影响力提升到配置目标的玩家立即获胜。

当前标准参数：

| 项目 | 参数 |
|---|---:|
| 影响力目标 | 18 |
| 轮次上限 | 18 |
| 单轮影响力增长上限 | 6 |
| 单次常规影响力收益 | 1 至 2 |
| 单次影响力夺取 | 1 |

影响力在每个原子效果结束后立即检查。达到目标的瞬间结束对局，不需要等待回合结束。

如果第 18 轮结束仍无人达到目标，只比较最终影响力：

- 影响力更高者获胜。
- 影响力相同则平局。

## 三、牌组与开局

当前标准构筑：

| 项目 | 规则 |
|---|---:|
| 蓝图牌堆 | 24 张 |
| 同名牌上限 | 2 张 |
| 模型下限 | 6 张 |
| 技术或论文下限 | 5 张 |
| 招牌行动 | 2 张 |
| 起始蓝图手牌 | 5 张 |
| 起始行动手牌 | 先手 0，后手 1 |
| 蓝图手牌上限 | 5 |
| 行动手牌上限 | 3 |
| 每回合蓝图抽牌 | 1 |
| 蓝图分类保底 | 3 次抽取内至少出现组织、模型、技术或论文 |
| 每回合行动抽牌 | 4，随后弃置至上限 |

蓝图牌堆可以包含组织、模型、技术和论文。行动与世界事件不能进入蓝图牌堆。

开局先进入起手调度：

1. 可以返回任意数量起始蓝图牌。
2. 返回的牌洗回蓝图牌堆。
3. 抽取同样数量的替代牌。
4. 双方确认后进入第 1 轮。

首版没有二次调度惩罚。

## 四、资源

### 算力

算力是回合资源：

```text
算力上限 = min(9, 2 + 自己的回合序号)
```

每个自己的回合开始时，算力恢复至当前上限。未使用算力不会保留。

### 资本

资本是跨回合资源：

```text
资本收入 = 1 + 组织收入 + 临时修正
资本上限 = 12
```

资本在回合开始时结算。超过上限的部分不会保留。

### 影响力

影响力是胜利进度，不是用于支付的货币。它只能通过 Benchmark、行动、组织触发、世界事件或明确效果增加。

同一来源实例每轮最多贡献一次影响力。其他资源或状态效果仍可按卡牌文本继续结算。

## 五、回合流程

每个完整轮次包含先手玩家回合和后手玩家回合。

单个回合按以下顺序执行：

1. 开始阶段。
2. 抽牌阶段。
3. 主要阶段。
4. 结束阶段。

### 开始阶段

- 自己的回合序号加一。
- 刷新算力。
- 获得资本收入。
- 触发回合开始效果。
- 检查状态合法性。

### 抽牌阶段

- 抽取 1 张蓝图牌，蓝图手牌可以暂时超过上限。
- 蓝图分为组织、模型、技术或论文三类；任一类别连续 3 次未出现时，下一次优先抽取该类别。
- 抽取 4 张行动牌。此时行动手牌可以暂时超过上限。
- 主要阶段可以正常使用手牌，也可以主动通过 `discard_action` 弃置。
- 结束回合时必须确保蓝图手牌不超过 5 张、行动手牌不超过 3 张。
- 如果使用行动后已经降到上限以内，不需要额外弃置。
- 蓝图手牌满时仍继续抽牌，超出上限的蓝图可在主要阶段使用或弃置。

### 主要阶段

当前标准每回合允许：

| 行动 | 每回合上限 |
|---|---:|
| 部署组织 | 1 |
| 部署资产 | 2 |
| 发起 Benchmark | 1 |
| 完成技术检定 | 1 |

玩家可以调整守擂模型、使用任意张资源允许的行动，并在完成后结束回合。

### 结束阶段

- 结算回合结束触发。
- 刷新或消耗状态持续时间。
- 回到蓝图与行动手牌上限。
- 清理临时费用和临时能力修正。
- 重置本回合行动计数。
- 检查影响力与终局。

## 六、牌桌区域

| 区域 | 规则 |
|---|---|
| 主实验室 | 固定存在，默认容量 2，提供基础部署位置 |
| 据点槽位 | 3 个，可部署组织 |
| 资产槽位 | 默认每个据点 2 个，可安装模型或技术 |
| 据点状态 | 默认最多 2 个 |
| 模型状态 | 每个模型最多 1 个 |
| 蓝图手牌 | 上限 5 |
| 行动手牌 | 上限 3 |
| 归档区 | 已离开相应牌堆或手牌的牌 |

组织、模型和技术没有传统生命值。攻击通过资源、费用、得分、状态或影响力造成压力。

## 七、部署与费用

部署顺序：

1. 选择手牌中的卡。
2. 选择合法据点或槽位。
3. 读取基础费用。
4. 依次应用方针、事件、目标、持续效果和状态修正。
5. 检查最终费用与目标合法性。
6. 支付资源并结算部署触发。

当前费用上下限：

- 模型算力费用最低为 1。
- 组织资本费用最低为 1。
- 行动算力费用最低为 0。
- 资本费用最低为 0。
- 单卡减免最多 -3。
- 单卡增加最多 +3。

费用支付后，后续目标失效不会返还费用。

主实验室允许在没有组织时部署资产。普通公司模型需要满足兼容标签和阵营条件。

## 八、行动池

行动手牌来自动态行动池，不由玩家在赛前逐张编排。

行动池组成：

```text
12 张基础行动
+ 每个有效据点提供的行动组
+ 2 张赛前招牌行动
```

规则：

- 每轮根据当前据点重新构建行动池。
- 同名行动只进入一次候选池。
- 据点因 `outage` 等状态失效时，其行动组不进入候选池。
- 已经抽到手中的行动不会因来源据点退场立即消失。
- 抽到的行动必须仍在当前行动手牌中才能使用。

## 九、Benchmark

Benchmark 是比较模型公开能力并获取影响力的主要方式。

发起规则：

- 每回合最多发起一次。
- 必须从合法行动中选择。
- 必须选择当前具备资格的己方模型。
- 模型本轮参赛后不能再次参赛。

防守规则：

- 防守方可以公开指定守擂模型。
- 指定模型不能参赛时，自动使用当前能力得分最高的合格模型。
- 没有合格模型时，主动方达到公开门槛即可得分。

公开结果包含：

- 双方基础能力。
- 每条修正来源。
- 最终得分。
- 分差。
- 胜者。
- 承压时长。

分差达到大比分阈值时，败方模型承压更久。承压模型在状态结束前不能参赛。

## 十、状态

| 状态 | 效果 |
|---|---|
| heat | 下一次 Benchmark 得分 +1，参赛后消耗 |
| controversy | 来源提供影响力时 -1，持续两个目标回合 |
| outage | 据点行动组失效，旗下模型不能参赛，持续一个目标回合 |
| overload | 下一次从该据点部署模型时算力费用 +1，部署后消耗 |
| regulation | 闭源或前沿标签效果失效，持续两轮 |
| training | 当前目标回合不能参赛，下一次对应 Benchmark 能力 +1 后消耗 |
| fortify | 抵消下一次负面状态后消耗 |
| momentum | 下一张行动算力费用 -1，使用或目标回合结束后消耗 |
| pressure | 模型下一目标回合不能参赛 |

据点状态超过容量时由新状态替换旧状态。模型状态上限为 1。

## 十一、特效攻击

特效攻击不使用传统伤害。当前类型：

| 类型 | 真实结果 |
|---|---|
| 算力压制 | 减少对手算力 |
| 资本挤压 | 减少对手资本 |
| 评分压制 | 降低目标模型下一次 Benchmark 得分 |
| 状态攻击 | 施加争议、承压、过载、监管或停机 |
| 费用污染 | 增加指定卡牌或目标类别的下一次费用 |
| 影响力夺取 | 在双方空间足够时转移 1 点影响力 |

所有攻击都由结构化效果结算，Agent 不自行计算或修改状态。

## 十二、世界事件与技术检定

世界事件在配置轮次开始触发，持续配置轮数，并同时影响双方。新事件开始前会清理旧事件留下的对应临时修正。

技术检定由特定行动触发：

- 每题有 4 个选项。
- 答对执行强化效果。
- 答错仍执行基础效果。
- 超过服务端截止时间未作答按答错自动结算。
- 超时结算仍执行基础效果，不会取消行动。
- 答错不会取消整个行动。
- Agent 不会收到正确答案。

## 十三、隐藏信息与合法性

Agent 可以看到：

- 双方公开场面和资源。
- 自己的蓝图手牌、行动手牌和蓝图组成。
- 当前合法语义行动及其预览。
- 世界事件、Benchmark 结果和公开日志。

Agent 不能看到：

- 对手隐藏蓝图手牌。
- 对手行动手牌。
- 未来抽牌顺序。
- 技术检定正确答案。
- 对手研究地图或私人牌组编辑状态。

Agent 只能提交 `availableActions` 中的完整语义行动对象。`actionId` 和 `commandId` 由服务端处理。

## 十四、对局外边界

官方 Pi 对战 Agent 不参与：

- 牌组编辑。
- 研究地图推进。
- 卡牌解锁。
- 回放分析。

Agent 牌组在创建对局时由服务端按对阵财团随机生成。随机牌组必须满足本文件相同的构筑规则，并使用玩家财团的对立面作为主财团。

玩家在研究地图获得卡牌后，在牌组页调整下一场对局使用的蓝图和招牌行动。对局开始后，牌组与阵营配置锁定。
